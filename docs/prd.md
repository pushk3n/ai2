# ICFIE-YOLO 论文复现 PRD

## 1. 项目概述

### 1.1 项目名称
基于 ICFIE-YOLO 的低照度图像目标检测算法复现

### 1.2 项目背景
论文 md.md 提出了一种面向低照度目标检测的改进检测框架 ICFIE-YOLO。该方法以 YOLOv7 为基线，在输入端加入多尺度光照矫正网络 MSICN，在检测头侧加入特征交互增强模块 FIE，以解决低照度图像中目标特征弱、背景噪声强、局部光照不均导致检测性能下降的问题。

当前需求不是撰写论文解读，而是形成一份可直接指导工程复现、实验推进和结果验收的 PRD，用于统一实现目标、数据流程、模型拆解、实验计划和交付标准。

### 1.3 项目目标
复现论文中的 ICFIE-YOLO 核心方法，并完成以下目标：

- 完成 ICFIE-YOLO 核心网络结构搭建，包括 MSICN 与 FIE 两个关键模块。
- 基于 YOLOv7 主干完成低照度目标检测训练与推理流程。
- 在 ExDark 数据集上完成主实验复现，输出 mAP、Recall 等关键指标。
- 在 DarkFace 数据集上完成泛化实验复现，验证方法迁移能力。
- 完成消融实验，验证 MSICN、FIE、GIC、LIC 的独立贡献。
- 输出可复用代码工程、训练脚本、配置文件、实验日志和复现报告。

### 1.4 成功定义
当以下条件满足时，视为项目达到复现目标：

- 模型可以稳定完成训练、验证与推理，训练过程无结构性报错。
- ICFIE-YOLO 相比 YOLOv7 基线在 ExDark 上有稳定正向提升。
- 至少完成一组主实验、一组消融实验和一组可视化实验。
- 输出的结果、配置、权重、日志可被他人复跑。


## 2. 复现范围

### 2.1 范围内
- 论文核心模型 ICFIE-YOLO 的工程复现。
- MSICN 结构实现：IFE、GIC、LIC、NLIS。
- FIE 结构实现：空间交互增强分支、通道交互增强分支、特征拼接融合。
- 基于检测损失的对齐训练流程。
- ExDark 与 DarkFace 数据集训练、验证、测试流程。
- 与 YOLOv7 基线对比实验。
- 模块消融实验和检测可视化。

### 2.2 范围外
- 不复现论文中所有对比方法，如 PE-YOLO、MAET、RetinexFormer+YOLOv7 等完整训练过程。
- 不优先复现论文全部表格中的所有横向对比结果。
- 不在第一阶段做模型压缩、量化、部署优化。
- 不在第一阶段追求与论文逐项完全一致的全部数值，只要求达到“趋势一致、核心结论成立”。

## 4. 需求拆解

### 4.1 业务需求
- 需要一个比 YOLOv7 基线更适合低照度场景的检测模型。
- 需要模型在不依赖成对低照度/正常照度数据的前提下可训练。
- 需要能够解释模型提升来自哪里，而不是只给最终指标。

### 4.2 功能需求

#### FR-1 数据处理能力
- 支持 ExDark、DarkFace 数据集导入。
- 支持标注转换为 YOLOv7 训练格式。
- 支持训练集、验证集、测试集划分与记录。

#### FR-2 模型构建能力
- 支持加载 YOLOv7 预训练权重。
- 支持在输入端插入 MSICN。
- 支持在 3 个尺度检测特征上插入 FIE。
- 支持开关控制模块，便于消融实验。

#### FR-3 训练能力
- 支持冻结主干训练与解冻微调两阶段训练。
- 支持仅通过检测损失优化 MSICN。
- 支持混合精度训练、断点恢复、日志记录。

#### FR-4 评估能力
- 支持 mAP、Precision、Recall 指标评估。
- 支持按类别输出 AP。
- 支持与基线模型对比。
- 支持输出可视化检测结果和特征热力图。

#### FR-5 实验管理能力
- 支持配置文件管理超参数。
- 支持实验版本命名、权重保存、日志归档。
- 支持输出复现报告与结论汇总。

### 4.3 非功能需求
- 代码结构清晰，模块职责明确，可单独调试。
- 支持单卡 GPU 训练，优先兼容消费级显卡环境。
- 训练和推理结果可复现，核心随机种子可固定。
- 具备基本可维护性，便于后续继续做轻量化和改进实验。


## 5. 技术方案规划

### 5.1 技术选型
建议采用 PyTorch 作为复现框架，理由如下：

- YOLOv7 官方实现和社区复现生态主要基于 PyTorch。
- 便于直接继承 YOLOv7 的训练框架、损失函数与权重加载方式。
- 便于快速做模块插拔、消融实验和可视化调试。

说明：论文中提到实验使用 TensorFlow 搭建，但从复现效率、资料完整性和社区生态出发，工程实现建议以 PyTorch 为主，只要网络结构、计算过程、训练策略和评价流程对齐即可。

### 5.2 系统整体流程
整体流程如下：

1. 输入低照度图像。
2. 图像先进入 MSICN 做光照矫正。
3. 矫正后的图像送入 YOLOv7 Backbone 提取多尺度特征。
4. 在 P3、P4、P5 三个尺度特征上加入 FIE 进行特征增强与噪声抑制。
5. 检测头输出分类、回归、置信度结果。
6. 通过检测损失完成训练，通过 NMS 输出最终预测框。

### 5.3 核心模块拆解

#### 模块 A：MSICN 多尺度光照矫正网络
目标：在不引入图像重建损失的前提下，仅利用检测损失驱动低照度图像向“更利于检测”的方向调整。

子模块要求：

- IFE：使用多层 3×3 卷积提取多尺度光照特征，输出 32 通道光照特征。
- GIC：根据光照特征输出全局光照系数 k，按 RGB 三通道独立调整。
- LIC：输出 10 组局部光照矫正参数，每组对应 3 通道局部调整。
- NLIS：将 GIC 与 LIC 输出的参数通过迭代非线性曲线作用于输入图像，保证输出仍在 [0,1] 范围内。

实现约束：

- GIC 输出必须经过 Sigmoid，确保 k 在 (0,1)。
- LIC 输出必须经过 2Sigmoid(x)-1，确保局部参数在 (-1,1)。
- NLIS 不含可训练参数。
- MSICN 输出图像尺寸与输入图像一致。

#### 模块 B：FIE 特征交互增强检测头
目标：通过空间关联和通道关联建模，增强有效目标特征，抑制背景和噪声干扰。

子模块要求：

- 空间分支：通过 1×1 卷积生成 b、c、d，并构建像素级相关矩阵。
- 通道分支：通过卷积压缩空间尺寸后生成 x、y、z，并构建通道级相关矩阵。
- 融合方式：将原始特征 f 与空间增强特征 f_s、通道增强特征 f_c 按通道拼接。

实现约束：

- FIE 需对三个尺度特征分别生效。
- 通道分支若发生空间压缩，concat 前必须上采样回原特征尺寸。
- FIE 模块应支持开关，便于消融。

#### 模块 C：YOLOv7 检测基线
目标：作为主干特征提取与检测框架，提供基线性能和训练基础。

要求：

- 直接基于成熟 YOLOv7 工程修改，避免从零重写检测器。
- 保持原有损失函数、标签分配、NMS、评估逻辑尽量不变。
- 仅在输入端和检测头前增加模块，减少不必要偏差。


## 6. 数据方案

### 6.1 数据集

#### ExDark
- 用途：主实验数据集。
- 类别数：12 类。
- 规模：7363 张图像。
- 参考划分：训练集 5890，测试集 1473。

#### DarkFace
- 用途：泛化实验数据集。
- 类别数：1 类人脸检测。
- 规模：6000 张图像。
- 参考划分：训练集 5400，测试集 600。

### 6.2 数据处理要求
- 统一标注格式到 YOLOv7 所需格式。
- 明确记录图像尺寸缩放、数据增强、类别映射关系。
- 数据划分文件需固化保存，避免不同轮次划分不一致。
- 若无法完全复用论文划分，则需在报告中显式记录差异。

### 6.3 数据风险
- ExDark 与 DarkFace 官方版本、标注版本可能存在差异。
- 论文未给出完整划分文件时，复现结果会出现正常波动。
- DarkFace 的低照度程度更强，小目标更多，对训练稳定性要求更高。


## 7. 训练方案

### 7.1 训练阶段规划

#### 阶段 1：基线复现
- 先跑通 YOLOv7 在 ExDark 和 DarkFace 上的基线训练。
- 输出基线指标，作为后续增强模块对照组。

#### 阶段 2：加入 MSICN
- 在输入端插入 MSICN。
- 冻结 YOLOv7 主干主要参数，仅训练 MSICN 与必要检测层。
- 使用检测损失单独优化 MSICN，验证其是否带来 Recall 提升。

#### 阶段 3：加入 FIE
- 在 P3/P4/P5 检测特征上加入 FIE。
- 验证 mAP 是否进一步提升。
- 对比“仅 FIE”和“MSICN+FIE”的差异。

#### 阶段 4：全模型微调
- 解冻主要检测网络参数。
- 使用较小学习率进行联合微调。
- 固定评估流程，输出最终结果。

### 7.2 推荐训练配置
建议作为首版默认配置：

- 输入尺寸：416×416 起步，复现稳定后可扩展到 640×640。
- 初始化权重：YOLOv7 在 COCO 上的预训练权重。
- 优化器：优先复现论文设定，可先使用 Adam；若训练不稳，再补充 SGD 对照。
- 初始学习率：1e-2。
- 最低学习率：1e-5。
- 混合精度：开启。
- Batch Size：按显存动态调整，优先保证训练可运行。
- 随机种子：固定。

说明：论文给出的是方向性训练设定，实际工程中应优先保证可训练和可收敛，再逐步贴近论文超参数。


## 8. 实验设计

### 8.1 主实验
目标：验证 ICFIE-YOLO 相对 YOLOv7 的整体提升。

输出内容：

- ExDark 上各类别 AP 与 mAP。
- DarkFace 上 AP、Precision、Recall。
- 与 YOLOv7 基线结果对比表。

### 8.2 消融实验
至少包含以下组合：

- YOLOv7 基线。
- YOLOv7 + MSICN。
- YOLOv7 + FIE。
- YOLOv7 + GIC + LIC。
- YOLOv7 + GIC + LIC + FIE。
- YOLOv7 + LIC + FIE。
- YOLOv7 + GIC + FIE。

目标：验证论文声称的两个核心结论：

- MSICN 主要改善目标可检出性，倾向提升 Recall。
- FIE 主要改善特征表达质量，倾向提升 mAP 和分类准确率。

### 8.3 可视化实验
- 原图与 MSICN 输出图像对比。
- 基线模型与 ICFIE-YOLO 检测框可视化对比。
- 加入/不加入 FIE 的特征热力图对比。

### 8.4 性能代价实验
- 统计参数量。
- 统计单张图推理时间。
- 对比 YOLOv7 与 ICFIE-YOLO 的速度和额外开销。


## 9. 验收标准

### 9.1 工程验收
- 代码可一键启动训练、验证、推理。
- 配置、权重、日志目录规范。
- 每个关键模块均可单独开关。

### 9.2 指标验收
采用“分层验收”方式：

#### A 级：强复现
- ExDark 上相对 YOLOv7 基线提升接近论文趋势，mAP 提升约 1.5 到 2.5 个百分点。
- DarkFace 上 AP 明显高于 YOLOv7 基线。

#### B 级：有效复现
- ExDark 上 ICFIE-YOLO 稳定优于 YOLOv7 基线。
- DarkFace 上至少在 AP 或 Recall 维度取得正向提升。
- 消融实验趋势与论文一致。

#### C 级：可运行复现
- 模型结构和训练流程全部跑通。
- 主实验、消融实验可输出结果，但绝对数值与论文仍有偏差。

### 9.3 结果解释验收
若数值未达到论文结果，仍需能明确解释原因，至少包括：

- 数据划分差异。
- 框架实现差异。
- 训练轮次或算力限制。
- 超参数未完全对齐。

## 11. 风险与对策

### 风险 1：论文细节缺失
表现：部分卷积层通道数、训练轮次、冻结范围、数据划分细节未完全公开。

对策：

- 先保证结构和公式一致。
- 对缺失部分采用最小偏置实现。
- 在实验记录中显式标记“论文未披露，工程侧补充设定”。

### 风险 2：结果难以完全对齐
表现：即使结构正确，指标也可能与论文存在差异。

对策：

- 优先验证趋势而非单点数值。
- 固定随机种子并重复实验至少 2 到 3 次。
- 保留基线与模块增益对照，而不是只看最终最优值。

### 风险 3：FIE 显存开销较大
表现：空间关联和通道关联计算可能增大显存与耗时。

对策：

- 优先在 416 输入尺寸上完成验证。
- 在实现时检查矩阵乘法维度，避免无效 expand。
- 必要时先仅在一个尺度验证，再扩展到三尺度。

### 风险 4：MSICN 输出不稳定
表现：若 NLIS 实现错误，可能导致图像越界、训练发散或梯度异常。

对策：

- 单独验证 MSICN 输出值域是否稳定在 [0,1]。
- 对 GIC、LIC 输出做数值监控。
- 在训练前先做前向单测和可视化抽检。

## 13. 推荐实施顺序
建议按以下顺序推进，避免一次性改动过大：

1. 先复现 YOLOv7 基线。
2. 单独接入 MSICN，确认输入输出和检测损失反向传播正确。
3. 跑通 YOLOv7 + MSICN，并验证 Recall 是否提升。
4. 单独接入 FIE，确认三个尺度特征尺寸与拼接正确。
5. 跑通 YOLOv7 + FIE，再与基线比较。
6. 最后组合成完整 ICFIE-YOLO，做联合微调。
7. 完成消融、可视化和性能代价分析。


## 14. 立项结论
该项目适合作为“中等复杂度、强实验驱动”的论文复现任务推进。其难点不在于目标检测主框架本身，而在于两个新增模块的数值稳定性、接入位置、训练策略以及与基线对齐方式。若按照“先基线、再单模块、后整合”的路线推进，项目成功率较高。

本 PRD 建议将第一阶段目标定义为“完成可运行且趋势正确的有效复现”，在此基础上再追求与论文更接近的最终数值。
